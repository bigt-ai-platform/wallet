# FIAT（法定通貨）決済 — WeChat / Alipay / 銀行または PayPal で BIG を交換

**用語。** FIAT = 法定通貨、CNY = 人民元、USD = 米ドル、P2P = ピアツーピア。

**これは何か。** Bigtangle ウォレットでは、**BIG** を法定通貨（WeChat Pay / Alipay / 銀行、または **PayPal USD**）と直接交換できます。売り手の BIG はまず、売り手・買い手・プラットフォームの三者中二者の同意がなければ動かせない**エスクローアドレス**に預けられます。買い手は代金を売り手へ直接支払い、売り手が自分の明細で確認してから BIG を解放します。プラットフォームはあなたの資金を保管せず、法定通貨にも触れません。

**スクリーンショットについて。** 以下のスクリーンショットは実機のデモ環境で撮影したものです。金額とハッシュはデモ用のデータで、実際の資金は関与しません。

このガイドでは、売り手が BIG を出品し、買い手が購入し、エスクローが確保され、買い手が支払い、売り手が確認して BIG を解放するまで、さらにタイムアウト時の返金までを説明します。レートは **BIG/CNY = 0.01**、注文は **10,000 BIG → 100 CNY** です。

## フローの概要

```
マッチング待ち → マッチング済み → エスクロー確保済み → 支払い待ち → 支払い申告済み → 入金確認済み → エスクロー解放済み → 完了
```

各ステップはアプリの取引カードに表示されます。状態は前にしか進まず、飛ばしたり戻ったりすることはありません。

任意の経路：支払い後に双方が争った場合は、取引を凍結して紛争を申し立て、プラットフォームの支援による裁定（買い手への送金、または売り手への返金）を受けることができます。


**PayPal（米ドル）。** **PayPal** を選ぶと、法定通貨は自動的に **USD** に切り替わり、受取口座が PayPal のメールアドレスになります。以降の流れはまったく同じです。詳しいデモは [p2p-paypal.zh.md](p2p-paypal.zh.md) → `assets/p2p-paypal.zh.mobile.pdf`（**10,000 BIG → 100 USD**）をご覧ください。

## 1. 売り手が受取プロフィールを保存

売り手は **P2P → マイ取引** を開き、受取方法（WeChat、Alipay、銀行、PayPal）を選んで、名義と口座番号を入力します（PayPal はメールアドレス）。この情報は取引が成立した後で買い手にだけ表示され、公開の注文板には表示されません。

![売り手が WeChat 支払いプロフィールを保存](assets/screenshots/p2p-cny-wechat-01-profile-ja.png)

---

## 2. 売り手が BIG を出品

売り手は **売り注文を出す** で、トークン（`bc`）、数量 **10,000**、価格 **0.01**、法定通貨 **CNY**、受取方法 **WeChat** を入力して出品します。

出品すると、売り注文は公開の注文板に **マッチング待ち** として表示されます。売り手は未成立の注文をいつでも取り消せます。

![wechat / CNY で売り注文を掲載](assets/screenshots/p2p-cny-wechat-02-order-ja.png)

---

## 3. 買い手が注文をマッチング

買い手は売り注文を開き、BIG を受け取るアドレスを入力して購入を確定します。この時点で WeChat や Alipay のアカウントを入力する必要はありません。売り手の受取情報は、エスクロー確保後にこの買い手にだけ個別に表示されます。

アプリはこの取引に一意の取引番号を作成し、エスクローアドレスを用意します。状態は **マッチング済み** になります。

![買い手が受取アドレスを入力](assets/screenshots/p2p-cny-wechat-03-match-ja.png)

![マッチング済みで作成された取引](assets/screenshots/p2p-cny-wechat-04-matched-ja.png)

---

## 4. 売り手が BIG をエスクローにロック

アプリはこの取引のために **2-of-3 エスクローアドレス** を生成します。売り手・買い手・プラットフォームの三者中いずれか二者の同意がなければ資金を動かせず、一方だけでは持ち出せません。

売り手は **10,000 BIG** をこのアドレスに送金し、アプリにその送金の取引ハッシュを貼り付けます。アプリが金額と宛先アドレスを照合すると、状態は **エスクロー確保済み** になります。買い手は法定通貨を支払う前に、BIG がすでに確保されていることを確認できます。

![売り手がエスクローの取引ハッシュを貼り付け](assets/screenshots/p2p-cny-wechat-05-escrow-lock-ja.png)

![エスクロー確保済み](assets/screenshots/p2p-cny-wechat-06-escrow-locked-ja.png)

---

## 5. 買い手が支払い手順を取得

買い手が **支払い詳細** をタップすると、次の内容が表示されます：

- 売り手の名義
- 受取口座（WeChat / Alipay / 銀行口座、または PayPal のメールアドレス）
- 正確な金額 **100 CNY**
- この取引専用の**備考コード**
- 支払い期限

買い手は送金時に必ず備考欄へ備考コードを記入します。状態は **支払い待ち** になります。期限を過ぎても支払いがない場合、取引は失効して返金されます。

![支払い手順：名義、口座、100 CNY、備考](assets/screenshots/p2p-cny-wechat-08-instructions-ja.png)

---

## 6. 買い手が CNY を支払って申告

買い手は自分の WeChat で **100 CNY** を送金し、備考に備考コードを記入したうえで、取引番号（振込番号）を **取引番号** に貼り付け、**支払いました** を押します。

支払いの証拠画像を添付することもできます。画像はサーバー側にのみ保存され、チェーンには書き込まれません。

![取引番号（振込番号）を入力済み](assets/screenshots/p2p-cny-wechat-09-payment-pending-ja.png)

状態は **支払い申告済み** になります。この時点でも BIG はロックされたままで、これはあくまで買い手の支払い申告です。

![支払い申告済み](assets/screenshots/p2p-cny-wechat-10-payment-claimed-ja.png)

---

## 7. 売り手が自分の明細で確認

売り手の取引カードには、買い手が入力した振込番号と備考が表示されます。売り手は自分の WeChat 明細で **金額 + 備考 + 時刻 + 振込番号** を照合し、間違いがないことを確認してから **入金を確認** を押します。

スクリーンショットは証拠になりません。自分の口座への実際の入金を基準にしてください。

![売り手に振込番号と確認の警告が表示される](assets/screenshots/p2p-cny-wechat-11-seller-confirm-ja.png)

状態は **入金確認済み** になります。

![入金確認済み](assets/screenshots/p2p-cny-wechat-12-payment-verified-ja.png)

---

## 8. 売り手がエスクローを解放

> **売り手はできるだけ早くエスクローを解放してください。** 入金を確認したらすぐに **資金を解放** を押してください。解放が遅れると売り手の評価が下がり、深刻な場合や繰り返しの場合は売り手が **不安全** と表示され、以降の注文に影響します。

入金確認後すぐに **資金を解放** を押すと、プラットフォームが共同署名し、BIG が買い手の受取アドレスに送金されます。売り手の署名とプラットフォームの署名の二つで解放が完了し、どちらか一方だけでは資金を動かせません。

売り手が直接受け取るため、追加の法定通貨送金のステップはなく、取引はそのまま終了します。

![エスクロー解放済み](assets/screenshots/p2p-cny-wechat-13-escrow-released-ja.png)

![完了](assets/screenshots/p2p-cny-wechat-14-completed-ja.png)

状態は **完了** になります。

---

## 9. 任意：紛争はプラットフォームの支援で裁定

支払いについて双方が争う場合（金額の不一致、未着金、売り手がなかなか解放しないなど）、どちらの当事者でも取引を凍結して紛争を申し立てられます。プラットフォームはエスクローと支払いの証拠を確認したうえで、**買い手への送金** か **売り手への返金** を決定します。

売り手の敗訴や度重なる遅延は信用に記録され、深刻な場合は **不安全** と表示されます。

---

## 10. タイムアウトまたは失敗 → 返金

買い手が支払わないままの場合、売り手は取引を失効させることができます。エスクローの BIG は買い手の同意なしに売り手へ戻ります。

どちらの当事者も相手の資金を保持することはありません。

---

## 11. 任意：「自分のスマホで確認」（買い手、解放の遅延時）

これは通常の決済に必要なステップではありません。売り手の解放が遅れた場合（買い手が支払いを申告してから **30 分** を超えた、または確認済みなのに解放されない）**または** 紛争が開始されている場合にのみ、買い手に **「自分のスマホで確認」** が表示されます。

これは **Alipay / 銀行** でのみ表示されます。買い手側で送金記録を読み取れるためです。WeChat は受取側への通知しかなく、PayPal には読み取りの仕組みがないため、どちらも表示されません。買い手は自分のペアリング済みスマホで一度読み取り、ウォレットがその結果に署名して送信します。この確認は売り手の信用に記録されますが、売り手が速やかに行うべき解放の代わりにはなりません。

---

## 比較：Binance P2P と今回の決済

| 機能 | Binance P2P | 今回の決済 |
|---|---|---|
| 法定通貨の検証 | 売り手が「確認」をクリック（評価システム） | 売り手が自分の明細で確認し、プラットフォームが手順に沿って資金を解放 |
| 法定通貨の預託 | プラットフォーム（買い手 → 売り手） | 買い手が売り手へ直接支払い、プラットフォームは法定通貨に触れない |
| エスクロー | プラットフォーム内部の台帳 | オンチェーンの 2-of-3 エスクローで、誰でも確認可能 |
| 返金 | サポートへのチケット | 取引の失効時に自動で売り手へ返金 |
| 紛争解決 | 有人サポート（数日） | アプリ内の紛争 + プラットフォームの裁定（より迅速） |

## タイムライン

```
マッチング済み      14:20  マッチング時に金額を固定
エスクロー確保済み  14:23  売り手が BIG を送金し、アプリが着金を確認
支払い待ち          14:24  買い手が支払い手順を確認
支払い申告済み      14:25  買い手が支払い、振込番号を入力
入金確認済み        14:26  売り手が自分の明細で確認
エスクロー解放済み  14:27  売り手とプラットフォームが共同署名し、BIG が買い手へ
完了                14:27  取引終了
```
