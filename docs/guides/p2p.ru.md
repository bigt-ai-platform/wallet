# P2P-расчёты — межрельсовый обмен с проверкой ИИ

**Статус: целевой дизайн, ещё не реализован.** Ниже описан процесс расчётов, который мы строим: 2-of-3 P2SH-эскроу на Bigtangle L0 и настоящая проверка через PayPal API. Сегодняшняя демо-сборка — конечный автомат поверх Postgres с имитированной фиатной стороной. Снимки экрана сделаны с этой демо-сборки; дизайн находится в репозитории dai, `docs/p2p.md`.

Это руководство демонстрирует расчёты P2P нативного ИИ: размещение USDT на продажу, матчинг с покупателем, блокировку эскроу, автоматическую проверку фиатного платежа, выпуск эскроу и возврат по тайм-ауту. Никакой ручной кнопки «Подтвердить» — механизм расчётов проверяет платёж по вебхуку PayPal.

---

P2P-панель показывает все активные обмены с текущим статусом, курсом и ссылками на транзакции.

![Панель](demo-output/screenshots/p2p-dashboard-ru.png)

Панель показывает все активные обмены: статус, курс и ссылки на транзакции. На каждой карточке — ID обмена, пара активов (например, 100 USDT ⇄ 101 USD), цветной бейдж статуса и раскрывающаяся временная шкала.

---

## 2. Продавец размещает USDT

Продавец отправляет лимитный ордер с подписью DID в механизм расчётов.

```typescript
const signature = signPayload(
  { sellerDid, giveToken: "USDT", giveAmount: "100",
    giveChain: "L0", wantCurrency: "USD",
    wantAmount: "101", wantRail: "paypal" },
  sellerPriv,
);
```

Продавец отправляет подписанный лимитный ордер: продать 100 USDT за 101 USD через PayPal. Механизм проверяет подпись DID. Статус: ACTIVE. Ордер истекает после validUntil.

---

## 3. Покупатель сопоставляет ордер

Покупатель отправляет подписанный рыночный ордер. Курс фиксируется в момент матчинга через оракул, а сумма счёта закрепляется с этого момента.

```typescript
const signature = signPayload(
  { orderId, buyerDid, amount: "100",
    receiveAddress, paypalAccount },
  buyerPriv,
);
```

Покупатель сопоставляет ордер подписанным рыночным ордером DID, указывая адрес для выпуска эскроу и PayPal-счёт для оплаты. Статус: MATCHED. Для всего жизненного цикла создаётся уникальный swapId.

---

## 4. Продавец блокирует USDT в эскроу 2-of-3

Адрес эскроу — это P2SH-скрипт с тремя ключами: продавец, покупатель, механизм — и порогом в два.

```typescript
// redeemScript = OP_2 <seller> <buyer> <engine> OP_3 OP_CHECKMULTISIG
const escrowAddress = p2shAddress(sellerPub, buyerPub, enginePub);
await L0.transfer(escrowAddress, "100");
```

Продавец пополняет адрес эскроу на Bigtangle L0. Механизм доказывает блокировку через `getTransactionStatus` — `CONFIRMED`, назначение `escrowAddress`, сумма 100 — и закрывается при любой неудачной проверке из трёх. Статус: ESCROW_LOCKED. Покупатель видит защищённые средства до отправки фиата.

---

## 5. Механизм выставляет счёт, покупатель платит через PayPal

Механизм создаёт PayPal-счёт на точную сумму и передаёт покупателю хостинговый URL.

```typescript
const res = await fetch("/api/p2p/payments/invoice", {
  method: "POST",
  body: JSON.stringify({ swapId, amount: "101", currency: "USD" }),
});
// → хостинговый URL оплаты; номер счёта = swapId
```

Покупатель оплачивает хостинговый счёт. Механизм не трогает деньги — их держит PayPal. Подтверждение продавца не требуется. Статус: PAYMENT_PENDING. Запускается таймер тайм-аута.

---

## 6. Механизм автоматически проверяет платёж

**Ключевое решение**: нет ручной кнопки «Подтвердить». Платёж доказывается PayPal, а не заявляется стороной.

```typescript
// POST /api/webhooks/paypal — SHA256withRSA over transmissionId|time|webhookId|crc32(body)
const ok = verifyPayPalWebhook(rawBody, headers);
if (ok) await transitions(swapId, "verify");
```

Механизм проверяет вебхук `INVOICING.INVOICE.PAID`, дедуплицируя по `event.id`. Это заменяет ручную кнопку «Подтвердить» из Binance P2P. Ни один продавец не сможет солгать о неполучении. Статус: PAYMENT_VERIFIED.

---

## 7. Механизм и покупатель выпускают эскроу

Две подписи удовлетворяют скрипт: подписи покупателя и механизма. Ни одна сторона в одиночку не может сдвинуть средства.

```typescript
const scriptSig = updateScriptWithSignature(unsigned, [
  await buyerKey.signInput(tx, 0),
  await engineKey.signInput(tx, 0),
  redeemScript,
]);
await L0.submitTransaction(serialize(tx));
```

Транзакция выпуска собирается и транслируется на `receiveAddress`. Статус: ESCROW_RELEASED. Покупатель теперь держит токены; оставшаяся работа механизма — фиатный выплат.

---

## 8. Механизм выплачивает продавцу

Механизм отправляет USD на PayPal продавца через Payouts v1, идемпотентно по обмену.

```typescript
const res = await fetch("/api/p2p/payments/payout", {
  method: "POST",
  body: JSON.stringify({ swapId, amount: "101", paypalAccount: sellerPaypal }),
});
// → PayPal-Request-Id: swapId, sender_batch_id: swapId
```

Механизм отправляет USD на PayPal продавца. Обмен COMPLETED. Общее время: ~3-5 минут. Всё подписано DID, каждый шаг аудируем в цепочке или в PayPal.

---

## 9. Тайм-аут или сбой → возврат

Если счёт так и не оплачен, механизм и продавец подписывают тот же скрипт обратно продавцу.

```typescript
const scriptSig = updateScriptWithSignature(unsigned, [
  await engineKey.signInput(tx, 0),
  await sellerKey.signInput(tx, 0),
  redeemScript,
]);
await L0.submitTransaction(serialize(tx));
```

Для возврата не нужны согласие покупателя и таймлок — порог достигается двумя другими ключами. Статус: EXPIRED → ESCROW_REFUNDED. Ни одна сторона никогда не держала средства другой стороны.

## Сравнение: Binance P2P vs расчёты ИИ

| Возможность | Binance P2P | Расчёты ИИ |
|---------|-------------|---------------|
| Проверка фиата | Продавец жмёт «Подтвердить» (система чести) | Вебхук PayPal, проверка RSA (детерминированно) |
| Хранение фиата | P2P (покупатель → продавец) | PayPal держит до выплаты (покупатель → PayPal → продавец) |
| Эскроу | Внутренний реестр | 2-of-3 P2SH на Bigtangle L0 (проверяемо) |
| Возврат | Тикет в поддержку | Механизм и продавец подписывают вместе, без согласия покупателя |
| Разрешение споров | Живая поддержка (дни) | Ончейн-доказательство + событие PayPal (минуты) |

## Полный демо-поток

```typescript
// 1. Продавец отправляет подписанный лимитный ордер (POST /api/p2p/orders)
// 2. Покупатель сопоставляет подписанным рыночным ордером (POST /api/p2p/orders/:id/match)
// 3. Продавец пополняет 2-of-3 P2SH-эскроу на L0; механизм доказывает (getTransactionStatus)
// 4. Механизм выставляет PayPal-счёт; покупатель платит (POST /api/p2p/payments/invoice)
// 5. Механизм проверяет вебхук INVOICING.INVOICE.PAID (POST /api/webhooks/paypal)
// 6. Механизм + покупатель подписывают выпуск (POST .../transitions, action: release)
// 7. Механизм выплачивает продавцу (POST /api/p2p/payments/payout)
// 8. Обе стороны видят статус COMPLETED на панели
```

Ключевое отличие от Binance P2P: **нет кнопки «Подтвердить» у продавца.** Платёж доказывается вебхуком PayPal, а средства лежат в 2-of-3-скрипте, которым не управляет ни одна сторона поодиночке — детерминированно, аудируемо, мгновенно.
