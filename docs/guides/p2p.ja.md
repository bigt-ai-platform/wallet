# P2P 決済 — ウォレット内蔵の人民元交換

**これは何か。** **Bigtangle L0** 上の暗号資産と人民元の法定通貨（WeChat Pay / Alipay / 銀行）との二者間交換です。売り手はトークンを **2-of-3 P2SH アドレス**（売り手・買い手・エンジン）に預託し、買い手は自身の決済アプリで売り手に**直接**支払い、売り手は自身の明細で入金を確認して預託が解放されます。不可逆な手順はすべてウォレット自身の PQ 鍵で署名され、エンジンは支出に**共同署名**できるだけです — あなたの資金を保有することはなく、法定通貨に触れることもありません。

**どこで。** ウォレットの **P2P** 画面（サイドバー → Trade → P2P）。以下はすべて、ローカルのデモビルドにあるこの画面から取得したものです。

**デモと本番。** スクリーンショットはデモビルドによるものです。エンジンはメモリストアで動作しチェーン検査を行わないため、lock / release の各手順は合成トランザクションハッシュを使います。状態機械、署名、追記専用のイベントログ、オンチェーンの監査アンカーは本物で、L0 ブロードキャストのみがスタブです。

**売り手の確認が法定通貨のシグナルです。** 個人の WeChat / Alipay / 銀行口座には入金 API がないため、待つべき機械検証可能な支払いイベントはありません。売り手は**自分のアプリで金額 + 備考 + 時刻 + 取引番号を確認し** — スクリーンショットは決して証拠になりません — 確認します。設計の詳細は `docs/p2p.md` にあります。

---

## 流れの概要

```
ACTIVE ──match──▶ MATCHED ──lock──▶ ESCROW_LOCKED ──instructions──▶ PAYMENT_PENDING
                                                                          │
   PAYMENT_PENDING ──proof──▶ PAYMENT_CLAIMED ──confirm──▶ PAYMENT_VERIFIED
                                                                  │
                            PAYMENT_VERIFIED ──release──▶ ESCROW_RELEASED ──complete──▶ COMPLETED
```

| # | 手順 | 実行者 | オンチェーン / エンジン |
|---|---|---|---|
| 1 | 売り手が人民元の入金プロフィールを保存 | 売り手 | プロフィールはサーバー側に保存、オーダーブックには入らない |
| 2 | 売り手が署名済みの売り注文を掲載 | 売り手 | 注文を保存、未資金化 |
| 3 | 買い手がマッチ（受取アドレス） | 買い手 | `swapId` を作成、預託アドレスを導出 |
| 4 | 売り手が 2-of-3 預託に資金を入れ、エンジンがロックを証明 | 売り手 + エンジン | L0 上で `ESCROW_LOCKED` |
| 5 | 買い手が支払い指示を取得 | 買い手 | `PAYMENT_PENDING`（+ スワップごとの備考） |
| 6 | 買い手が自分のアプリで支払い、取引番号で申請 | 買い手 | `PAYMENT_CLAIMED` |
| 7 | 売り手が自分の明細を確認して確定 | 売り手 | `PAYMENT_VERIFIED` |
| 8 | エンジンがトークンを解放、交換が完了 | エンジン | `ESCROW_RELEASED` → `COMPLETED` |

すべての遷移は `social.p2p-swap` レコードとして L1-SOCIAL チェーンにアンカーされ、どちらの当事者の口座情報も露出せずにライフサイクル全体を公開監査できます。

---

## 1. 売り手が入金プロフィールを保存

**My swaps** タブで、売り手はレール（WeChat、Alipay、銀行）を選び、受取人の名前と口座を入力します。プロフィールは売り手の DID の下でサーバー側に保存され、公開オーダーブックの一部では**ありません** — 指示の呼び出しによって、マッチした買い手にのみ開示されます。

![売り手が WeChat 入金プロフィールを保存](/demo/p2p/p2p-cny-wechat-01-profile-ja.png)

---

## 2. 売り手が売り注文を掲載

**Open sells** タブで注文を入力します。与えるトークンと数量、希望する人民元価格、トークンが載るチェーン、そして**支払い方法**（wechat / alipay / bank）です。人民元レールを選ぶと通貨が CNY に切り替わります。条件は掲載時に注文に固定されるため、これはウォレット鍵で署名されます：

![売り注文フォーム、wechat レール付き](/demo/p2p/p2p-cny-wechat-02-order-ja.png)

掲載すると、注文はエンジン内で `ACTIVE` になり、公開オーダーブックに表示されます（個人情報は含みません）。

---

## 3. 買い手がマッチ

買い手は注文を開き、解放されるトークンの**受取アドレス**を入力します。マッチは買い手の支払いを約束させるため、これも署名されます：

![買い手が受取アドレスを入力](/demo/p2p/p2p-cny-wechat-03-match-ja.png)

エンジンはライフサイクル用の一意な `swapId` を作成し、交換は `MATCHED` になり、買い手の **My swaps** タブに表示されます：

![交換は MATCHED](/demo/p2p/p2p-cny-wechat-04-matched-ja.png)

---

## 4. 預託ロック — 売り手が L0 に資金を入れる

売り手はトークンを決定論的な 2-of-3 預託アドレスへ送り、その転送の `txHash` を報告します。エンジンはチェーンからロックを証明し（`CONFIRMED`、宛先が `escrowAddress`、金額が一致）、いずれかの検査が成立しなければフェイルクローズします：

![売り手が預託トランザクションハッシュを貼り付け](/demo/p2p/p2p-cny-wechat-05-escrow-lock-ja.png)

交換は `ESCROW_LOCKED` になります。買い手は法定通貨を支払う**前に**資金が確保されたことを確認でき、**Payment details**（支払い詳細）アクションが与えられます：

![ESCROW_LOCKED](/demo/p2p/p2p-cny-wechat-06-escrow-locked-ja.png)

---

## 5. 買い手が支払い指示を取得

買い手が **Payment details** を押すと、エンジンは売り手のプロフィールを開示し、振込が*必ず*付帯しなければならない**スワップごとの備考コード**、ならびに正確な金額と期限を発行します。指示は交換カードにインラインで表示されます：

![支払い指示：受取人名、口座、715 CNY、備考](/demo/p2p/p2p-cny-wechat-08-instructions-ja.png)

交換は `PAYMENT_PENDING` になり、タイムアウトタイマーが始まります — 買い手が支払わなければ、売り手は買い手の同意なしに期限切れにして預託を返金できます。

---

## 6. 買い手が支払い、取引番号で申請

買い手は自身の WeChat / Alipay / 銀行アプリで正確な金額を振り込み、取引番号を **Transaction ID** に貼り付け、**I have paid** を押します。任意の領収書画像はサーバー側に保存され、その `sha256` のみが交換イベントにアンカーされます：

![Transaction ID（取引番号）を入力](/demo/p2p/p2p-cny-wechat-09-payment-pending-ja.png)

ステータスは `PAYMENT_CLAIMED` になります — **トークンはまだロックされています。** この状態は純粋に買い手の申請として存在します：

![PAYMENT_CLAIMED](/demo/p2p/p2p-cny-wechat-10-payment-claimed-ja.png)

---

## 7. 売り手が自分の明細で確認

売り手のカードには買い手の取引番号と備考が表示されます。売り手は**自分の口座で金額 + 備考 + 時刻 + 取引番号を確認**し、それからようやく **Confirm received** を押します：

![売り手が取引番号と確認警告を見る](/demo/p2p/p2p-cny-wechat-11-seller-confirm-ja.png)

交換は `PAYMENT_VERIFIED` になります：

![PAYMENT_VERIFIED](/demo/p2p/p2p-cny-wechat-12-payment-verified-ja.png)

---

## 8. 解放 — 資金が移動

解放は預託されたトークンを移動します。売り手（事前署名または共同署名）とエンジンが預託出力の支出にそれぞれ署名し、2 つの署名が 2-of-3 スクリプトを満たします。トークンは買い手の受取アドレスに届きます：

![ESCROW_RELEASED](/demo/p2p/p2p-cny-wechat-13-escrow-released-ja.png)

売り手が直接支払われたため、法定通貨の支払い手順はありません — 交換が完了します：

![COMPLETED](/demo/p2p/p2p-cny-wechat-14-completed-ja.png)

---

## 任意 — 自分のスマホによる自動確認

ステップ 7 は通常、手動のタップです。エンジンに確認させるには、スマホを一度
ペアリングし、**売り手自身**の受領記録を読ませます — 売り手が手作業で確認する
のと同じ明細を自動で読み取ります。

**スマホをペアリング（1 回）。** ご自身のスマホに **Mobile Agent** アプリ
([`android-remote-control-mcp`](https://github.com/danielealbano/android-remote-control-mcp))
をインストールします。これは *スマホ上で* MCP サーバーを動かします（ユーザー
補助サービス、adb 不要）。ユーザー補助を許可し、サーバーを起動して、表示される
エンドポイントと**短い単回使用コード**を控えます。ウォレットで **Device** を
開き、**Pair with code** を押してエンドポイントとコードを入力します。ペアリング
はいつでも **Settings › Access › Paired devices** で取り消せます。

**スワップを検証。** スワップカードで **Verify with my phone** を押します —
どちらの当事者も自分の端末を検証できます。エンジンはペアリングした
エンドポイントに接続し、あなた自身の決済アプリから該当する明細（金額・備考・
時刻・取引番号）を読み取り、その後 **ウォレットが判定に署名**します。Alipay と
銀行は画面をユーザー補助に公開しますが、WeChat は UI を隠すため、WeChat では
アプリが WeChat 自身の「入金通知」を読み取ります:

![受取人の WeChat 入金通知](/demo/p2p/p2p-verify-wechat-notification-en.png)

**何が変わるか。** 既定では読み取りは紛争の証拠にすぎません。
`SETTLEMENT_CNY_AUTO_RELEASE_ON` ポリシー（`seller_receipt`、またはより厳格な
`two_sided` / `verified_receipt`）では、条件を満たす読み取りが**手動確認の代わり
になり**、エスクローを解放します。これは依然としてアテステーションであり、
オラクルではありません。ペアリングが同意であり、いつでも取り消せ、エンジンは
あなたがペアリングした側だけを読み取ります。

## あなたを守るもの

| リスク | 緩和策 |
|---|---|
| 相手が立ち去る | 資金は 2-of-3 P2SH アドレスにあり、誰も単独では動かせない |
| 不足または過剰な支払い | 金額はマッチ時に固定され、指示には正確な数字とスワップごとの備考が付く |
| 偽の支払い申請 | 買い手の申請だけでは決して解放されない — 売り手が自分の明細で確認する |
| 売り手が未入金を主張 | 仲裁；チェーン記録と証明ストアが証拠 |
| エンジンが不正 | エンジン専用の手順はエンジン DID 署名を要し、すべての遷移がアンカーされ公開監査可能 |
| 紛争 | どちらの当事者も交換を凍結できる；解決までトークンはロックされたまま |
| 返金 | `expire` → `refund`、エンジンと売り手が共同署名 — 買い手の同意不要、タイムロックなし |

---

## 本番へ

デモはメモリストアとチェーン検査なしのリポジトリ内の決済サービスに対して動作します。実際のフローでは預託署名器を L0 ブロードキャスト手順に接続し、エンジンを L1-SOCIAL に対して実行してオーダーブックと監査アンカーを担わせます。買い手は売り手に直接支払い、エンジンは依然として共同署名しか行いません。
